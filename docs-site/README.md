# oto docs site

A [Starlight](https://starlight.astro.build) mirror of oto's Markdown
documentation. It renders the docs that already live in this repository; it is
not a second place to write them.

**It is deployed.** [`.github/workflows/pages.yml`](../.github/workflows/pages.yml)
builds this directory on every push to `main` that touches a source doc, and
publishes it to GitHub Pages at <https://thulasi-ram.github.io/oto>.

The workflow builds from **source**, not from the committed mirror: `npm run
build` runs the sync first, so a commit that edited a doc without re-syncing
still deploys the correct page. Re-sync anyway — the committed mirror is what
makes a docs change reviewable in a diff.

## Running it

```
npm install
npm run dev          # syncs, then serves on localhost:4321/oto/
npm run build        # syncs, then builds to ./dist/
npm run check-links  # every internal link in ./dist/ resolves
npm run verify       # build + check-links, which is what CI runs
```

`dev` and `build` both run the sync step first, so a stale mirror cannot survive
either command. `npm run sync-docs` runs it on its own. `just docs-check` from
the repository root is `npm run verify`.

Note the `/oto/` in the dev URL: the site is served from a path, not a domain
root, and the dev server mirrors that so a link that would 404 in production
404s locally too.

## Where the site lives, and the trap in it

[`site.config.mjs`](site.config.mjs) holds `site` and `base`, and **both
`astro.config.mjs` and `scripts/sync-docs.mjs` read it.** That sharing is not
tidiness. Astro applies `base` to the URLs it generates — assets, sidebar,
search — and cannot apply it to an href sitting in Markdown, because it cannot
tell a route it produced from a string somebody typed. The sync script produces
those strings, so the sync script prefixes them.

Set `base` in `astro.config.mjs` alone and the result is the confusing kind of
broken: the nav works, the stylesheet loads, every page renders, and all ~280
in-content links 404. `npm run check-links` exists to make that a failed build
rather than a discovery.

Moving to a custom domain served at the root is `base: "/"` in that one file,
plus a re-sync.

## How the sync works

`scripts/sync-docs.mjs` copies Markdown from the repository into
`src/content/docs/` and turns it into Starlight pages:

| Source | Becomes |
|---|---|
| `README.md` | `guides/overview.md` |
| `CONTEXT.md` | `architecture.md` |
| `CONTRIBUTING.md` | `contributing.md` |
| `docs/releasing.md` | `releasing.md` |
| `docs/concepts.md` | `concepts.md` |
| `docs/ORCHESTRATION.md` | `orchestration.md` |
| `docs/adr/*.md` | `adr/` |
| `docs/design/*.md` | `design/` |
| `docs/setup/*.md` | `setup/` |
| `docs/runbooks/*.md` | `runbooks/` (`README.md` becomes `index.md`) |

For each file it derives the frontmatter `title` from the first H1, strips that
now-redundant H1 from the body, and rewrites `*.md` links to the clean URLs
Starlight serves them at. The four directory mirrors are deleted and rebuilt on
every run, so a page removed from `docs/` does not linger.

The generated pages are committed, which means they can go stale between a
source edit and the next sync. Re-run the sync after any change under `docs/`,
or to `README.md`, `CONTEXT.md`, `CONTRIBUTING.md` or `docs/concepts.md`, and
commit the result with the source change.

## Layout

- `site.config.mjs` — `site` and `base`, read by the Astro config AND the sync
  script. See above for why that is shared rather than repeated.
- `astro.config.mjs` — site config and the hand-written sidebar. Overview is
  listed explicitly; Design, ADRs, Setup and Runbooks are autogenerated from the
  mirrored directories, so a new file in one of those needs no config change.
- `scripts/check-links.mjs` — the gate CI runs: every internal link in `dist/`
  resolves, carries the base, and is not a `.md` path the sync could not rewrite.
- `src/content/docs/` — generated pages, plus the two hand-authored ones:
  `index.mdx` and anything else under `guides/` that is not `overview.md`.
- `src/styles/custom.css` — theme overrides.
- `public/` — static assets served as-is.
